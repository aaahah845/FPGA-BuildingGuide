# 可配置文字与 SITE.CFG V6

本副本可以在电脑端输入标题、楼层名、房间名、房间简介和活动文字。导出工具从电脑字体生成本次配置需要的字模，与图片索引一起放进同一个 `SITE.CFG`。第一次需要下载本副本对应的动态文字位流；此后换文字只需重新导出、复制配置到 SD 卡并重新启动，不必重新综合 FPGA。

## 操作

1. 使用 UTF-8 文本编辑器修改 `config/runtime_site.json`。只改文字时，保留 `images`、`photo_image`、`point_photo_image` 和地图坐标等字段。
2. 首次使用安装依赖：`python -m pip install -r scripts/requirements_dynamic_text.txt`。
3. 在本工程目录运行 `python scripts/export_site_cfg.py`。
4. 导出成功后，将 `config/sd_card/SITE.CFG` 复制到 SD 卡根目录，与 JSON 中列出的 BMP 文件配套使用。开发板断电后插好卡，再上电。

不要手工修改二进制 `SITE.CFG`。不要修改两个 `glyph_catalog.json` 文件：它们现在用于保留固定界面的字模编号及 ABI 校验，并不是新文字的白名单。

示例：

```json
"title": "校园导览终端"
```

房间字段可以写为：

```json
"name": "物理实验室",
"description": "用于日常教学与学生实践。",
"today_activity": true,
"activity": "实验课程，请按时到场。"
```

校园完整示例见 `config/examples/runtime_school.json`，沿用现有图片与坐标，只修改名称和说明。导出命令：

```powershell
python scripts/export_site_cfg.py config/examples/runtime_school.json -o config/examples/SITE_SCHOOL.CFG
```

使用时将输出文件改名为 `SITE.CFG`。示例中的图片仍是原场景图片，并未自动变成学校照片。

## 输入范围

| 内容 | 上限 |
| --- | --- |
| 标题、每层名称、每个房间名称 | 每项 1～8 个字符；标题不能全部为空格 |
| 每个房间简介、每项活动 | 每项最多 4 行，每行 12 字；长行自动换行，允许 `\n` 显式换行 |
| 全部标题/楼层/房间名称共用字库 | 121 个不同的动态字符，另有空格及“企业会议导视”固定字符可免费复用 |
| 全部简介/活动共用字库 | 85 个不同的动态字符，另有空格及“房间简介今日活动暂无”固定字符可复用 |

字数包括字母、数字和标点；重复字只占一个字模槽。两套字库分别统计，同一个字在名称和简介中出现会在两套字库各占一个槽。固定界面按钮、状态标签仍由 FPGA 自带字模显示。

默认使用 Windows 微软雅黑，名称为 24×24 粗体字模，说明为 16×16 常规字模。工具检查字体的 Unicode cmap，不支持的字符会明确报错，不会默默导出“方框”。可以通过 `--large-font 路径` 和 `--notes-font 路径` 指定其他 TTF/OTF/TTC 字体；TTC 使用第 0 个字体。每个 Unicode 字符按一个固定格显示，不支持组合字符、控制字符、emoji 组合序列或复杂文字连写排版。

这里的“任意输入”指在字体支持和上述容量内自由选择文字，不代表无限字数或完整 Unicode 字库常驻 FPGA。导出时提示超出字符容量，应减少整套配置中的不同字数；改变同一名称多次不会累积占用，下一次导出重新统计整套配置。

## 版本配套

V6 文件为 27,648 字节，包含完整动态字模。它必须与本副本的动态文字位流配套。旧 8 KB V5 文件不能用于新位流，新 V6 文件也不能用于旧位流。旧工程与其原配置保持独立，可成对恢复。

配置载入完成前画面为黑色，HDMI 时序仍正常输出。若数码管报配置错误 9，先检查卡根目录是否为新导出的 27,648 字节 `SITE.CFG`；文件缺失、损坏或读取失败也会拒绝启动场景。

`base_fonts/fixed_ui_base.bin` 保存固定 UI 字模的基准快照，`manifest.json` 保存 SHA-256 及编号表。正常导出不依赖 RTL 源码；这两个文件必须和导出脚本一起保留。
